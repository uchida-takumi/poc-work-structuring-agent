# [Task] 計画担当者向けダッシュボードの要件定義

## 親Issue
[Issue 02: 需要予測AIと生産計画連携の高度化](02_demand_forecasting_and_production_planning.md)

## 背景
需要予測AIと生産計画連携の仕組みを現場の計画担当者が使いこなすためには、直感的で意思決定を支援するダッシュボードが必要である。AIの予測結果を透明性高く提示し、担当者が安心して承認・修正判断できる操作インタフェースを設計する。

## 目的
- 計画担当者が週次の計画更新サイクルを短縮できる操作性の実現
- AIによる予測根拠の可視化（説明可能AI）で担当者のAI受容性を高める
- 計画承認・修正のワークフローを一元化し、属人的なExcel作業を排除する

## スコープ

### ダッシュボード画面構成

#### 1. トップページ（週次計画サマリー）
- **今週の要対応件数**: 承認待ち予測数、異常アラート数、シナリオ検討中件数
- **主要KPIサマリー**: 全体の需要充足率、在庫日数、前週比変動Top5車種
- **アクションリスト**: 期限付き承認待ちタスクの一覧（優先度順）

#### 2. 需要予測ビュー
- **予測一覧テーブル**: 車種×地域×週の予測台数、信頼区間、前週予測との差分
- **時系列グラフ**: 実績・予測・信頼区間の重ね書きチャート（13週表示）
- **予測精度モニター**: 直近4週のMAPE推移、モデル健全性インジケーター
- **フィルタ・ソート**: 車種コード、地域コード、変動率、ステータスで絞り込み
- **説明可能AI（XAI）パネル**: 選択した予測に対する寄与度の高い特徴量Top5（SHAP値ベース）

#### 3. 計画承認ワークフロー
- **承認待ち一覧**: 要承認の予測/計画改定を一覧表示（締切・担当・変動幅）
- **詳細確認モーダル**: 予測値、信頼区間、シナリオ比較リンク、変更理由
- **承認操作**:
  - AI予測通り承認（1クリック）
  - 台数を手動調整して承認（数値入力フィールド）
  - 差し戻し・否認（コメント入力）
- **一括承認**: フィルタ後の複数件を一括承認（変動±3%以内のみ対象）
- **承認履歴**: 過去の承認/否認ログの検索・閲覧

#### 4. シナリオ比較ビュー（Issue 02c と連携）
- シナリオ選択（最大3シナリオ並列）
- KPI比較テーブル（充足率・在庫・コスト影響）
- 週次時系列グラフの重ね書き
- シナリオ採用→承認フローへの連携ボタン

#### 5. アラート・通知センター
- **アラート種別**:
  - 予測精度劣化（MAPE閾値超過）
  - 需要急変（前週比±X%超）
  - 承認期限超過（24h未承認）
  - 部品制約/物流遅延発生（Issue 03/05連携）
- **通知チャネル**: ダッシュボード内通知、メール通知（設定可能）

#### 6. 運用レポートビュー
- バックテスト結果サマリー（過去3か月）
- モデル精度トレンドグラフ（週次MAPE推移）
- 計画改定リードタイム計測（自動集計）
- 承認率・手動修正率のトレンド

### 非機能要件

| 要件 | 目標値 |
|------|--------|
| 画面初期表示 | 3秒以内（P95） |
| 予測データ更新反映 | バッチ完了後5分以内 |
| 同時接続ユーザー数 | 50ユーザー以上 |
| 対応ブラウザ | Chrome/Edge 最新2バージョン |
| レスポンシブ対応 | デスクトップ（1280px以上）優先、タブレット参照可 |
| 多言語対応 | 日本語（初期）、英語（将来対応） |

### アクセス制御・ロール設計

| ロール | 閲覧 | 承認 | 設定変更 |
|--------|------|------|---------|
| 計画担当者 | ○（担当範囲） | ○（担当範囲） | △（個人設定のみ） |
| 計画マネージャー | ○（全体） | ○（全体） | ○ |
| 閲覧専用（マーケ等） | ○（読み取りのみ） | ✗ | ✗ |
| システム管理者 | ○ | ○ | ○（全設定） |

### 運用手順書の整備要件
- ダッシュボード操作マニュアル（画面キャプチャ付き）
- 週次計画更新の標準作業手順（SOP）
- アラート対応フロー（種別ごとの判断基準と対応手順）
- トラブルシューティングガイド

## 完了条件（Definition of Done）
- 全6画面のワイヤーフレームが計画担当者レビュー済み
- 非機能要件（レスポンス・同時接続数）のPoC検証完了
- ロール設計がセキュリティ部門の承認済み
- 操作マニュアル（日本語版）の初版が作成・承認済み
- 週次計画更新SOPが計画部門の合意済み
- ユーザー受け入れテスト（UAT）計画書が作成済み

## 依存関係

- Issue 02c（シナリオ比較）: シナリオ比較ビューのデータ提供

## リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| UI複雑化による現場受容性低下 | 高 | 初期スコープを絞り、MVP（最小機能版）から段階リリース |
| XAIパネルの解釈しにくさ | 中 | UXデザイナーと計画担当者の共同ユーザーテストで改善 |
| 承認フロー変更による業務混乱 | 中 | 既存Excel運用との並行期間を設け段階移行 |
| パフォーマンス要件未達 | 低〜中 | フロントエンドの遅延ロード・ページネーション設計 |
