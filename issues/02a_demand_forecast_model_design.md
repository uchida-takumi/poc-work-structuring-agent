# [Task] 車種/地域/販社単位の需要予測モデル設計

## 親Issue
[Issue 02: 需要予測AIと生産計画連携の高度化](02_demand_forecasting_and_production_planning.md)

## 背景
現行の需要予測は統計モデル（移動平均・重回帰等）に依存しており、車種モデルチェンジや地域固有の需要変動、販促イベントへの対応が困難。車種・地域・販社の3軸で精度の高いAI予測モデルを構築し、在庫過不足を抑制する。

## 目的
- 車種/地域/販社の粒度で需要予測精度（MAPE）を現行比10%以上改善
- 週次サイクルでの予測更新を自動化し、計画改定リードタイムを短縮する

## スコープ

### 予測対象の定義
- **予測粒度**: 車種×販売地域×販社（最小単位）、集約は車種×地域（ダッシュボード表示用）
- **予測ホライズン**: 4週先（週次更新）、13週先（月次更新）
- **予測対象変数**: 受注台数、生産指示台数、納車台数

### 入力特徴量の設計
| カテゴリ | 特徴量例 | データソース |
|---------|---------|------------|
| 販売実績 | 過去受注台数、月次・週次トレンド | ERP/販売管理システム |
| 外部要因 | 金利動向、ガソリン価格、景気指数 | マーケ部門提供 |
| 販促計画 | キャンペーン期間・規模、値引き率 | 販売計画システム |
| 車種情報 | モデルサイクル年数、競合状況 | 商品企画部門 |
| 季節性 | 月次季節指数、祝日カレンダー | 内部算出 |
| 供給制約 | 部品制約フラグ（Issue 03連携） | 調達システム |

### モデルアーキテクチャ
- **候補モデル**: LightGBM（ベースライン）、Prophet（季節性特化）、LSTM/Transformer（時系列深層学習）
- **モデル選定基準**: MAPE、MAE、予測区間のカバレッジ、計算コスト
- **アンサンブル**: 単一モデルと複数モデルの加重平均を比較検証
- **階層予測**: 車種×地域×販社 → 車種×地域 → 車種 の集約整合性を保証（Reconciliation）

### 学習・更新サイクル
| タイミング | 処理内容 |
|-----------|---------|
| 週次（月曜朝） | 直近実績取り込み・予測値更新 |
| 月次 | 特徴量エンジニアリング見直し・ハイパーパラメータ再チューニング |
| モデル劣化検知時 | 自動再学習トリガー（MAPE閾値超過） |

### バックテスト設計
- **評価期間**: 直近3か月分のローリング評価（ウォークフォワード法）
- **ベースライン比較**: 現行統計モデルとの比較、ナイーブ予測との比較
- **評価指標**: MAPE、wMAPE（重み付き）、Bias（過多/過少予測傾向）、予測区間的中率

## 完了条件（Definition of Done）
- 予測粒度・ホライズン・入力特徴量の仕様書が承認済み
- 候補モデルのPoCバックテスト結果（3か月分）が完了し、現行比10%以上改善を確認
- モデル学習・更新パイプラインの設計書が完成
- 異常検知・再学習トリガー仕様が定義済み
- データサイエンティストと計画部門のレビュー承認済み

## 依存関係
- Issue 01（統合データ基盤）: 販売実績・部品制約データの提供
- 販売・マーケ部門: 外部要因データ（金利、販促計画等）の定期提供
- Issue 03（サプライヤーリスク）: 部品制約フラグの連携

## リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| 需要急変時（リコール、競合新車投入）のモデル劣化 | 高 | 残差モニタリングと閾値超過時の自動アラート・再学習 |
| 外部要因データの遅延・欠損 | 中 | フォールバック特徴量セットの設計（外部データなしでの予測） |
| 販社コード・車種マスタ不整合 | 中 | Issue 01のマスターデータ統合ルール適用 |
| 階層予測の集約不整合 | 低 | Reconciliationアルゴリズムの組み込み |
