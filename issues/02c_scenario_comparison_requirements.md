# [Task] シナリオ比較（通常/部品制約/物流遅延）機能の要件定義

## 親Issue
[Issue 02: 需要予測AIと生産計画連携の高度化](02_demand_forecasting_and_production_planning.md)

## 背景
需要予測と生産計画は「通常ケース」だけでなく、部品供給制約・物流遅延・需要急変といった例外シナリオにも対応する必要がある。計画担当者が複数シナリオを比較・評価した上で最適な生産計画を選択できる機能が求められる。

## 目的
- 部品制約・物流遅延などの外部リスク発生時に、代替計画を迅速に比較・選択できる意思決定支援を実現
- シナリオごとの影響分析（在庫差異、コスト増、顧客納期影響）を定量化して提示

## スコープ

### シナリオ種別定義

| シナリオID | シナリオ名 | 説明 |
|-----------|-----------|------|
| NORMAL | 通常シナリオ | 制約なし。需要予測モデルの標準出力をそのまま使用 |
| PARTS_CONSTRAINT | 部品制約シナリオ | 特定部品の供給制限（Issue 03連携）を加味し、生産上限を設定 |
| LOGISTICS_DELAY | 物流遅延シナリオ | 輸送遅延（Issue 05連携）により特定部品の到着が遅れるケースを反映 |
| DEMAND_SURGE | 需要急増シナリオ | 需要が予測上限を大幅に超えた場合の増産対応プランを検討 |
| DEMAND_DROP | 需要急減シナリオ | 需要が予測下限を下回った場合の減産・在庫調整プランを検討 |

### シナリオパラメータ設計

#### 部品制約シナリオ（PARTS_CONSTRAINT）
| パラメータ | 説明 | 入力元 |
|-----------|------|--------|
| constrained_parts | 制約対象部品コードリスト | Issue 03 / 調達部門入力 |
| constraint_rate | 供給可能率（0.0〜1.0） | Issue 03 / 手動入力 |
| constraint_duration_weeks | 制約継続見込み週数 | 調達部門入力 |
| affected_vehicles | 影響を受ける車種コードリスト | 自動算出（BOMトレース） |

#### 物流遅延シナリオ（LOGISTICS_DELAY）
| パラメータ | 説明 | 入力元 |
|-----------|------|--------|
| delay_route | 遅延発生輸送レーン | Issue 05連携 |
| delay_weeks | 遅延週数 | Issue 05連携 / 手動入力 |
| delay_probability | 遅延発生確率（0.0〜1.0） | Issue 05 予測モデル出力 |
| affected_parts | 影響部品コードリスト | 自動算出 |

### シナリオ比較計算ロジック

各シナリオについて以下の指標を自動計算：

| 指標 | 説明 |
|------|------|
| production_plan_units | シナリオ別の週次生産計画台数（車種×工場） |
| demand_fulfillment_rate | 需要充足率（生産台数 ÷ 予測需要台数） |
| inventory_projection | 計画期間末の在庫台数/日数 |
| backorder_units | バックオーダー（欠品）台数予測 |
| cost_impact | 追加コスト試算（緊急調達・代替輸送等） |
| revenue_risk | 需要充足率低下による逸失売上試算 |

### シナリオ比較画面の要件

1. **シナリオ並列表示**: 最大3シナリオを列形式で比較表示
2. **KPIサマリー**: 各シナリオの主要KPI（充足率・在庫・コスト影響）を横並びで表示
3. **週次時系列グラフ**: 予測期間（13週）の生産計画・需要予測・在庫推移を重ね書き
4. **インパクト差分ハイライト**: 通常シナリオとの差分が大きい項目を自動ハイライト
5. **シナリオ選択・適用**: 比較後に採用シナリオを選択し、Issue 02b の承認フローへ連携

### シナリオ保存・共有機能
- 作成したシナリオ設定の保存（名称・パラメータ・コメント）
- シナリオ比較結果のPDF/Excelエクスポート
- 計画会議向けの共有URL生成（閲覧専用）

### シナリオ実行のパフォーマンス要件
- シナリオ計算完了時間: 3シナリオ同時計算で60秒以内
- シナリオ履歴保持期間: 13週分の実行履歴

## 完了条件（Definition of Done）
- 5種のシナリオ定義とパラメータ仕様が承認済み
- シナリオ計算ロジックの仕様書（入出力・計算式）が完成
- シナリオ比較画面のワイヤーフレームが計画担当者レビュー済み
- Issue 03（サプライヤーリスク）・Issue 05（物流遅延）との連携インタフェースが合意済み
- パフォーマンス要件（60秒以内）がPoC検証済み

## リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| Issue 03/05からの連携データが未整備 | 高 | 手動入力によるシナリオパラメータ設定機能を先行リリース |
| BOMトレースによる影響車種計算の複雑性 | 中 | BOMマスタ精度の事前確認、段階的な対象車種拡大 |
| シナリオ数増加による計算コスト増 | 低〜中 | 非同期バッチ計算とキャッシュ戦略の設計 |
