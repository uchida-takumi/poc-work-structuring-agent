# [Feature] 需要予測AIと生産計画連携の高度化

## 背景
販売変動、モデル切替、地域別需要の揺らぎに対して、従来の計画プロセスではリードタイムが長く、在庫過不足が発生している。

## ユーザー課題
需給計画担当者が短サイクルで予測を更新できず、部品手配と生産配分の意思決定が後手になる。

## 提案内容
需要予測AIを導入し、生産計画システムに連携して計画改定を半自動化する。

## スコープ
- 車種/地域/販社単位の需要予測モデル設計 → [Issue 02a](02a_demand_forecast_model_design.md)
- 予測結果を生産計画に取り込むインタフェース設計 → [Issue 02b](02b_production_plan_interface_design.md)
- シナリオ比較（通常/部品制約/物流遅延）機能の要件定義 → [Issue 02c](02c_scenario_comparison_requirements.md)
- 計画担当者向けダッシュボードの要件定義 → [Issue 02d](02d_planning_dashboard_requirements.md)

## スコープ外
- 個別工場の生産実行システム（MES）の改修
- 部品調達先との外部データ連携（Issue 03 対応）
- 物流最適化ロジック（Issue 05 対応）

## 代替案
- 既存統計モデルのパラメータ改善のみで対応
- 地域別に手作業計画を継続

## 受け入れ条件
- 主要車種で現行比10%以上の予測誤差改善（MAPE等）
- 週次計画改定リードタイムを30%以上短縮
- 計画担当者の運用手順書が整備される
- 過去3か月分のバックテスト結果がレビュー承認される

- 統合データ基盤（Issue 01）
- 販売・マーケ部門の外部要因データ提供
- 在庫最適化AI（Issue 04）への予測値提供（下流依存）

## リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| 需要急変時のモデル劣化 | 高 | 異常検知ロジックとモデル再学習トリガーの実装 |
| 現場運用における説明可能性不足 | 中 | SHAP等の解釈可能AI手法の活用、運用手順書整備 |
| データ品質不足による精度低下 | 中 | Issue 01のデータ品質KPIとの連携、入力データ検証の実装 |
| 計画担当者の受容性 | 低〜中 | UI/UXへの現場意見反映、段階的ロールアウト |
