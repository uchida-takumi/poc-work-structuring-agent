# データ連携PoC実施報告書

## 概要

本書は、サプライチェーン統合データ基盤の代表拠点1箇所（第1工場: SITE-JP-0010）におけるデータ連携PoCの実施内容・結果・課題・推奨事項をまとめた報告書である。

| 項目 | 内容 |

## 2. PoC対象スコープ

### 2.1 対象システムと連携データ

| ドメイン | ソースシステム | 連携データ | 連携方式 |

| 調達 | SAP ERP（第1工場向け） | 入庫実績、PO、サプライヤーマスタ | CDC + 日次バッチ |

| 品質 | QMS_SIEMENS（第1工場検査ライン） | 受入検査実績、SPC測定データ | CDC + IoT |

## 4. 課題と対応策

### 4.1 技術的課題

| # | 課題 | 重大度 | 対応策 | 期限 |
|---|---|---|---|---|
| T-01 | Oracle Database 11g（WMS）のDebezium制約 | 高 | Oracle 19cへのアップグレード計画を策定（代替: 15分ポーリング） | 2026年Q3 |
| T-02 | MES設備の一部（旧型3台）がOPC-UAに未対応 | 中 | OPC-UA変換ゲートウェイの導入（Prosys OPC UA Server） | 2026年Q2 |
| T-03 | SAP ERPのSLT設定にSAP BASIS権限が必要でリードタイム長 | 低 | BASIS作業の定例化（月次窓枠での対応） | 2026年Q2 |

### 4.2 データ品質課題

| # | 課題 | 重大度 | 対応策 | 期限 |
|---|---|---|---|---|
| D-01 | 廃番部品コードが未クレンジング（マスタ不整合率の主因） | 高 | SAP ERP内の廃番品目の整理・有効終了日設定 | 2026年Q2 |
| D-02 | サプライヤーコードの部門間表記ゆれ | 高 | 調達部門主導でサプライヤーコード統一作業を実施 | 2026年Q2 |
| D-03 | MES生産実績の一部（段取り作業）がWOに紐付かない | 中 | MES設定変更で段取りWOを自動発行するよう改修 | 2026年Q3 |

### 4.3 運用課題

| # | 課題 | 重大度 | 対応策 | 期限 |
|---|---|---|---|---|
| O-01 | データ品質アラートの対応担当が未定 | 高 | データスチュワード役割の定義と担当者アサイン | 2026年Q2 |
| O-02 | バックフィル処理の優先度判断フローが不明確 | 中 | バックフィル対応手順書の整備 | 2026年Q2 |

## 5. 本番展開に向けた推奨事項

### 5.1 優先対応事項（本番展開前に必須）

1. **Oracle WMS アップグレード計画の承認** - データ基盤チーム + IT部門 + WMSオーナーで計画策定
2. **廃番部品コードクレンジング** - 調達部門主導で実施、データ基盤チームが支援
3. **サプライヤーコード統一** - 調達部門がデータ辞書に基づいて統一作業実施
4. **データスチュワード体制確立** - HR部門と各業務部門が役割・責任を確定

### 5.2 他拠点展開への推奨事項

1. **PoC経験の標準化:** 本報告書の課題・対応策を接続仕様書に反映
2. **段階的展開:** 第2工場（SITE-JP-0020）から始め、3ヶ月ごとに1拠点追加
3. **拠点固有のシステムバージョン確認:** OracleやMESのバージョン差異に注意
4. **名寄せ作業のリードタイム確保:** マスタ名寄せに2〜4週間を見込む
