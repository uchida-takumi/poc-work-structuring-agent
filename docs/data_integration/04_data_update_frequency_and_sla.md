# データ更新頻度およびSLA設計書

## 概要

本書は、サプライチェーン統合データ基盤における各データの更新頻度区分（リアルタイム・日次・週次）とSLA（Service Level Agreement）を定義する。AIユースケース要件に基づき、データ鮮度と処理コストのバランスを最適化する。

---

## 1. 更新頻度区分の定義

| 区分 | 定義 | 代表的なユースケース | 最大許容遅延 |
|---|---|---|---|
| **リアルタイム** | 事象発生後、原則5分以内にデータを反映 | 在庫移動、輸送状態、設備異常 | 5分 |
| **準リアルタイム** | 事象発生後15〜60分以内に反映 | 生産実績集計、検査結果 | 60分 |
| **日次（Intraday）** | 当日中（EOD）または翌営業日朝に反映 | 日次在庫確定値、発注データ | 翌日07:00 JST |
| **週次** | 週1回（通常週末バッチ）に反映 | マスターデータ更新、週次レポート | 月曜07:00 JST |
| **月次** | 月1回に反映 | 評価スコア更新、契約情報 | 翌月第1営業日09:00 JST |

## 3. SLA設計

### 3.1 可用性SLA

| サービスコンポーネント | 可用性目標 | 計画停止 | 計測期間 |
|---|---|---|---|
| データ取込パイプライン（全体） | 99.5%/月 | 日曜深夜2h以内 | 月次 |
| Kafkaクラスター | 99.9%/月 | 計画停止なし（ローリングアップデート） | 月次 |
| Data Lake（ADLS Gen2） | 99.99%/月 | Azure SLA準拠 | 月次 |
| 標準化処理バッチ | 99.5%/月 | 計画停止なし | 月次 |
| 分析/AI向け提供レイヤー | 99.0%/月 | 月次メンテナンス窓（3h以内） | 月次 |
| KPIダッシュボード（Power BI） | 99.0%/月 | 月次メンテナンス窓 | 月次 |

**可用性計算式:**
```
可用性 = (計測期間内分数 - ダウン分数) / 計測期間内分数 × 100
```

### 3.2 データ鮮度SLA（End-to-End）

データ鮮度SLAは「ソースシステムの事象発生からキュレーション層での利用可能状態」までを定義する。

| データ系統 | データ種別 | 鮮度SLA（P50） | 鮮度SLA（P99） |
|---|---|---|---|
| 調達 | 入庫実績 | ≦ 3分 | ≦ 10分 |
| 調達 | 日次PO | 07:00 JST | 08:00 JST |
| 生産 | WOイベント | ≦ 2分 | ≦ 10分 |
| 生産 | 設備テレメトリ | ≦ 1分 | ≦ 5分 |
| 在庫 | 在庫移動 | ≦ 3分 | ≦ 10分 |
| 在庫 | 日次スナップショット | 06:00 JST | 07:00 JST |
| 物流 | 輸送状態 | ≦ 5分 | ≦ 15分 |
| 品質 | SPC計測 | ≦ 1分 | ≦ 3分 |
| 品質 | 検査実績 | ≦ 3分 | ≦ 10分 |

### 3.3 スループットSLA

| パイプライン | 設計処理能力 | ピーク処理能力 |
|---|---|---|
| Kafka取込（全トピック合計） | 10,000 msg/秒 | 50,000 msg/秒 |
| 在庫移動CDC | 1,000 msg/秒 | 5,000 msg/秒 |
| 設備テレメトリ | 5,000 msg/秒 | 20,000 msg/秒 |
| 日次バッチ（全系統合計） | 50GB/日 | 200GB/日 |

### 3.4 インシデント対応SLA

| 重大度 | 定義 | 応答時間 | 復旧時間 |
|---|---|---|---|
| P1 - Critical | 全データパイプライン停止、AIモデル稼働停止 | 15分以内 | 2時間以内 |
| P2 - High | 特定系統のパイプライン停止（SLA違反） | 30分以内 | 4時間以内 |
| P3 - Medium | SLA軽微違反、品質アラート多発 | 2時間以内 | 翌営業日中 |
| P4 - Low | 非クリティカルな遅延・品質低下 | 翌営業日 | 1週間以内 |

## 4. 処理スケジュール設計

### 4.1 日次バッチスケジュール（Apache Airflow）

```
00:00 - 01:00  各業務系終日締め処理（ソースシステム側）
01:00 - 02:00  [調達] ERP差分抽出・転送
01:00 - 03:00  [在庫] WMSスナップショット抽出・転送
02:00 - 03:00  [物流] TMS輸送実績確定データ抽出
03:00 - 04:00  [品質] QMSクレームデータ抽出
03:00 - 05:00  Raw → Standardized 変換処理（全系統）
05:00 - 06:00  マスターデータ統合・ゴールデンレコード更新
05:30          [在庫] スナップショット利用可能化（SLA: 06:00）
06:00 - 07:00  Standardized → Curated 変換処理（特徴量生成）
06:30          [調達] POデータ利用可能化（SLA: 07:00）
07:00          全日次バッチ完了確認・品質チェックレポート送信
07:30 - 08:00  [AI] 在庫最適化・需要予測バッチ推論
08:00          [業務] KPIダッシュボード更新完了
```

### 4.2 週次バッチスケジュール

```
土曜 22:00 - 日曜 06:00  マスターデータ全量同期（部品/拠点/サプライヤー/車種）
日曜 00:00 - 06:00       マスター品質チェック・名寄せ処理
日曜 06:00               週次マスター更新完了確認
月曜 07:00               最新マスターを参照した週次集計テーブル更新完了
```

## 5. 障害・メンテナンス計画
